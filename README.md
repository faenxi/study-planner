# Study Planner

Лабораторна робота №8 — **React Fundamentals**: компоненти, JSX, props, стан, події та списки.

Study Planner — простий планувальник навчальних завдань. Дані зберігаються лише в пам'яті React
(після перезавантаження сторінки скидаються до початкових).

**Стек:** React 19, TypeScript, Vite, SCSS + BEM, ESLint.

## Запуск

Потрібен Node.js **22.22 або новіший** (`node -v`).

```bash
npm install
npm run dev      # дев-сервер, адреса покаже термінал
npm run lint     # ESLint
npm run build    # перевірка типів (tsc) і збірка
```

## Що вміє застосунок

- показує список завдань;
- додає нове завдання (назва обов'язкова, після додавання форма очищається);
- позначає завдання виконаним і повертає назад, видаляє завдання;
- показує статистику: всього / виконано / не виконано;
- фільтрує: Всі / Виконані / Не виконані (активний фільтр підсвічений);
- повідомлення для порожнього списку та для порожнього результату фільтра;
- додатково: лічильники в кнопках фільтра та кнопка «Очистити виконані».

`alert` не використовується: помилка валідації виводиться під полем.

```
src/

│   ├── TaskFilters.tsx   # кнопки фільтра
│   ├── TaskList.tsx      # список через map + умовний рендеринг
│   ├── TaskItem.tsx      # одне завдання
│   └── *.scss            # стилі кожного компонента (BEM)
├── data/
│   ├── initialTasks.ts   # початкові дані
│   └── labels.ts         # підписи пріоритетів і фільтрів
├── styles/               # токени, блок button, базові стилі
├── types/task.ts         # Task, Priority, TaskFilter, NewTask
├── App.tsx               # стан і обробники
└── main.tsx
```

```
App                    ← тут живе state: tasks, filter
├── Header
├── TaskForm           ← onAddTask (callback вгору)
├── TaskStats          ← tasks (props вниз)
└── section
    ├── TaskFilters    ← filter, counts, onFilterChange, onClearCompleted
    └── TaskList       ← tasks (вже відфільтровані), onToggle, onDelete
        └── TaskItem × N
```

Дані йдуть **вниз** через props, події йдуть **вгору** через callback-функції.

## Де що в коді (для захисту)

| Тема | Де дивитись |
|---|---|
| `useState` для списку та фільтра | `App.tsx`: `tasks`, `filter` |
| `useState` для полів форми | `TaskForm.tsx`: `values`, `titleError` |
| props та callback | `App.tsx` → `TaskList.tsx` → `TaskItem.tsx` (`onToggle`, `onDelete`) |
| список через `map` і `key` | `TaskList.tsx` (`key={task.id}`) |
| умовний рендеринг | `TaskList.tsx` (два порожні стани), `TaskItem.tsx` (опис, статус), `TaskFilters.tsx` (кнопка «Очистити виконані») |
| immutable update | `App.tsx`: `handleAddTask` (spread), `handleToggleTask` (`map`), `handleDeleteTask` (`filter`) |
| похідні дані (без окремого state) | `TaskStats.tsx` та `counts` в `App.tsx` |
| фільтрація без зміни масиву | `App.tsx`: `visibleTasks`, `matchesFilter` |
| валідація | `TaskForm.tsx`: `handleSubmit` |

## Стилізація: SCSS + BEM

Обрано один підхід: **SCSS + BEM**. Кожен компонент має свій `.scss` поруч із `.tsx`
і власний BEM-блок: `task-item`, `task-item__title`, `task-item--completed`.
Глобальними залишені лише базові стилі в `styles/main.scss` та спільний блок `button`.

## Контрольні запитання

**1. Що таке React-компонент і чому інтерфейс будується з компонентів?**
Компонент — це функція, яка повертає шматок інтерфейсу (JSX). Як деталі конструктора: `TaskItem` — одне завдання, `TaskList` складається з багатьох `TaskItem`. Так код ділиться на невеликі зрозумілі частини, їх можна використовувати повторно й змінювати окремо.

**2. Що таке JSX і чим відрізняється від HTML?**
JSX — синтаксис, який виглядає як HTML, але це JavaScript. Відмінності: `className` замість `class`, `htmlFor` замість `for`, атрибути пишуться в camelCase (`onClick`), усі теги мають бути закриті (`<input />`), а всередину можна вставляти JavaScript у `{}`.

**3. Чому JSX повертає один кореневий елемент або Fragment?**
Функція може повернути лише одне значення, тому всі елементи загортають в один спільний. Якщо зайвий `div` не потрібен, використовують Fragment: `<>...</>`.

**4. Як вставляється JavaScript-вираз?**
У фігурних дужках: `{task.title}`, `{tasks.length}`, `{task.completed ? 'Виконано' : 'Не виконано'}`. Можна вставляти вирази (значення), але не оператори на кшталт `if` чи `for`.

**5. Що таке props і як передаються?**
Props — вхідні дані компонента, як аргументи функції. Батько передає їх як атрибути: `<TaskItem task={task} onToggle={handleToggle} />`, а дочірній компонент отримує їх у параметрі: `function TaskItem({ task, onToggle })`.

**6. Чи може дочірній компонент змінювати props? Як передати callback?**
Ні, props тільки для читання. Щоб дитина могла щось змінити, батько передає **функцію** (callback), а дитина її викликає: `onClick={() => onToggle(task.id)}`. Саму зміну state виконує батько.

**7. Для чого `useState`? Що повертає?**
Щоб компонент «пам'ятав» значення між рендерами, а зміна значення оновлювала екран. Повертає масив із двох елементів: поточне значення і функцію для його зміни: `const [tasks, setTasks] = useState(initialTasks)`.

**8. Чому не можна напряму змінювати масив або об'єкт у state?**
React визначає, що state змінився, порівнюючи посилання. Якщо зробити `tasks.push(...)`, посилання лишається тим самим, React нічого не помічає і екран не оновлюється. Тому створюють новий масив або об'єкт.

**9. Різниця між `setState(value)` та `setState(prev => ...)`?**
`setState(value)` ставить готове значення. `setState(prev => ...)` отримує **актуальне** попереднє значення, тому безпечна, коли нове значення залежить від старого (наприклад, `setTasks(prev => prev.filter(...))`).

**10. Як React рендерить список через `map`?**
`map` перетворює масив даних на масив елементів JSX: `tasks.map(task => <TaskItem key={task.id} task={task} />)`. React виводить їх усі підряд.

**11. Для чого `key`? Чому індекс як key — проблема?**
`key` допомагає React зрозуміти, який елемент списку який, коли список змінюється. Індекс змінюється при видаленні чи вставленні: елементи «з'їжджають», і React може переплутати їхній state чи показати чужі дані. Тому використовують стабільний унікальний `id`.

**12. Що таке умовний рендеринг? Способи?**
Це показ різного інтерфейсу залежно від умови. Способи: `if` з раннім `return` (`TaskList`), тернарний оператор `cond ? A : B` (`TaskItem`), оператор `&&` (`{task.description && <p>...</p>}`).

**13. Локальний state і props?**
State належить самому компоненту і він сам його змінює (поля `TaskForm`). Props приходять ззовні від батька і дитина лише читає їх.

**14. Де зберігати state, який потрібен кільком дочірнім компонентам?**
У найближчому спільному батьківському компоненті, а дітям передавати через props (це називається «підняти state вгору»). У нас `tasks` живе в `App`, бо потрібен і `TaskList`, і `TaskStats`, і `TaskFilters`.

**15. Що відбувається після виклику setter-функції?**
React запам'ятовує нове значення, ставить компонент у чергу на повторний рендер і заново викликає функцію компонента з новим state. Потім оновлює на екрані лише те, що змінилось. Сама змінна в поточному рендері не змінюється.

**16. Чому статистику не обов'язково зберігати в окремому state?**
Її можна порахувати з масиву завдань під час рендеру (`tasks.filter(...).length`). Окремий state довелося б вручну синхронізувати з масивом, і про це легко забути. Такі значення називають похідними (derived).

**17. Що таке immutable update і як застосовується до масивів?**
Це зміна без модифікації старого значення: створюється нова копія. Додати: `[...prev, item]`. Змінити: `prev.map(t => t.id === id ? { ...t, completed: true } : t)`. Видалити: `prev.filter(t => t.id !== id)`. Не використовують `push`, `splice`, `sort` на самому state.
